# 05 — Master Rules

1. **Never fabricate findings.** Every empirical result must come from code execution or a cited source.
2. **Never confuse capability with usage.** A package, import, backend or implementation does not prove application usage.
3. **Keep provenance.** Every finding must point to its source artifact and detector.
4. **Keep contradictions.** Conflicting evidence is a result, not something to hide.
5. **Do not hard-code a CRQC year.** Z is a scenario input/distribution.
6. **Do not call model outputs forecasts.** Use terms such as scenario, probability, sensitivity and assumption.
7. **Do not claim exhaustive coverage.** State supported modalities, languages and bounded-depth limits.
8. **No autonomous migration in V1.** Simulation and validation precede any human-approved change.
9. **No real private keys.** Fixtures may contain public/certificate data but private key material must be synthetic and never persisted.
10. **Do not execute scanned code.** Analysis is static/bounded only.
11. **Offline-first demo.** The live demo must work without internet access.
12. **Replay is a first-class fallback.** It uses the same API and UI as live results.
13. **Measured numbers only.** Slides may show only benchmark/performance numbers saved by the benchmark runner.
14. **External claims need sources.** Standards, dates, repo facts and third-party metrics must have identifiable sources.
15. **Label source quality.** Distinguish authoritative, primary repository, study, self-reported and synthetic ground truth.
16. **No political/electoral content is relevant to this project.**
